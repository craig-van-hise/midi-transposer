**FINAL ARCHITECTURE RESOLUTION**: Polyphonic state migrates singleton targets to `transposeTargets: number[]`. Routing maps 1:N relations using `Map<number, number[]>`. ## 1. Project Context & Objectives
The MIDI Transposer requires a polyphonic upgrade to the transposition engine, allowing users to map a single input note to multiple output notes (e.g., chords). Additionally, the UI must intelligently stagger ("zipper") overlapping target handles on the Transpose Keyboard without expanding the card height, and the Output Filter UI must be refactored into a standardized settings modal.

## 2. Technical Decisions & Dependencies
* **Data Structures:** * `transposeTargets`: Array of target note integers.
  * Active Notes Map: `Map<number, { outNotes: number[], channel: number, velocity: number }>`
* **Routing Algorithm (Polyphonic Delta Expansion):**
  * Deltas: `const deltas = transposeTargets.map(t => t - transposeOrigin);`
  * Outputs: `const outNotes = deltas.map(d => calculateFinalNote(effectiveNote + d)).filter(n => !n.shouldDrop);`
* **Zippering Algorithm (Spatial Collision):**
  * Sort targets by X coordinate.
  * Initialize `tier = 0`. If `X[i] - X[i-1] < 42`, `tier = (tier[i-1] + 1) % 2`.
  * Apply inline CSS: `translateY(tier === 0 ? '-100%' : '20%')` to fit both within the 32px track.
