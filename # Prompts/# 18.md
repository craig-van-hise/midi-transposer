# Product Requirements Prompt (PRP) — 🔘 Pending

## 1. Project Context & Objectives
**Context:** The MIDI Transposer currently suffers from a state management bug ("hung notes"). When a user holds a physical key in the Play zone and simultaneously changes the `transposeTarget` (either via the Transpose zone or the UI), the subsequent `Note Off` message is sent to the *new* transposed pitch. The original transposed `Note On` is never turned off.
**Objective:** Architect a deterministic active-note tracking system within the MIDI routing engine. Implement three user-selectable `transposeHoldMode` behaviors (Sustain Original, Immediate Cutoff, Retrigger) and expose these settings via a new UI modal on the Transpose Keyboard.

## 2. Technical Decisions & Dependencies
* **State Management (Active Notes):** Do NOT track active notes in Zustand (this would cause massive React re-render floods). You must use a `useRef<Map>` inside `useWebMidi.ts` to track exact `incomingNote -> outNote` mappings.
* **Zustand Subscription:** To handle "Cutoff" and "Retrigger" modes when `transposeTarget` changes, do NOT add `transposeTarget` to the `useEffect` dependency array of the MIDI listener. Instead, utilize `useMidiStore.subscribe((state, prevState) => {...})` inside a dedicated `useEffect` to react to state changes without re-binding hardware listeners.
* **DRY Logic:** You will need to extract the inline Note Calculation & Filtering logic (currently lines 112-140 in `useWebMidi.ts`) into a reusable local helper function so it can be called by both incoming `Note On` events and the `Retrigger` loop.

### Phase 3: Cutoff & Retrigger Engine Engine — 🔵 Active
* **Objective:** React dynamically to `transposeTarget` changes based on the selected mode.
* **Instructions:**
    1.  In `useWebMidi.ts`, extract the mathematical filtering logic (currently inside `handleMidiMessage`) into a pure helper function *outside* the event listener but inside the hook:
        `const calculateFinalNote = (incomingNote: number, state: MidiStoreState) => { ...returns { outNote, shouldDrop } }`
    2.  Refactor `handleMidiMessage` to use this new helper.
    3.  Add a new `useEffect` in `useWebMidi.ts`:
        ```typescript
        useEffect(() => {
          const unsub = useMidiStore.subscribe((state, prevState) => {
            if (state.transposeTarget === prevState.transposeTarget) return;
            if (state.transposeHoldMode === 'sustain') return;

            activeRoutedNotes.current.forEach((activeData, incomingNote) => {
              // 1. Always send Note Off for the currently playing note
              state.midiOutputs.forEach(out => out.send(new Uint8Array([0x80 | activeData.channel, activeData.outNote, 0])));
              
              if (state.transposeHoldMode === 'cutoff') {
                activeRoutedNotes.current.delete(incomingNote);
              } 
              else if (state.transposeHoldMode === 'retrigger') {
                // 2. Calculate new note
                const { outNote: newOut, shouldDrop } = calculateFinalNote(incomingNote, state);
                if (!shouldDrop) {
                  // 3. Send new Note On and update Map
                  state.midiOutputs.forEach(out => out.send(new Uint8Array([0x90 | activeData.channel, newOut, activeData.velocity])));
                  activeRoutedNotes.current.set(incomingNote, { ...activeData, outNote: newOut });
                } else {
                  activeRoutedNotes.current.delete(incomingNote);
                }
              }
            });
          });
          return unsub;
        }, []);
        ```
* **TDD Checkpoint:**
