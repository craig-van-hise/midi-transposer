# Product Requirements Prompt (PRP) — WEB MIDI DIAGNOSTICS 🔘

## 1. Context & Objective
**STATUS: CRITICAL HARDWARE DIAGNOSTIC**
The Web MIDI API is failing silently. The hook is mounted but returning 0 devices or failing without UI feedback. We must surface the exact Web MIDI API promise state and errors directly into the Header UI so the user knows if it's a browser block, a permissions denial, or an exclusive OS lock.

## 2. Mandatory Execution Constraints
* **DO NOT** edit any `.md` files. 
* Target `.ts` and `.tsx` files ONLY.

## 3. Implementation Phases

### Phase 1: Diagnostic State (`useMidiStore.ts`) — [Status Marker] 🔘
* **Objective:** Add status tracking to the global store.
* **Instructions:**
  1. Open `src/store/useMidiStore.ts`.
  2. Add to `MidiStoreState` interface and store implementation: 
     * `midiAccessStatus: 'pending' | 'granted' | 'denied' | 'unsupported' | 'error'` (Default: `'pending'`).
     * `midiErrorText: string | null` (Default: `null`).
  3. Add setters: `setMidiAccessStatus` and `setMidiErrorText`.
* **AGENT INSTRUCTION:** "Set Phase status to 🔵 Active. Edit the store. Once applied, set status to ✅ Completed."

### Phase 2: Instrument the Hook (`useWebMidi.ts`) — [Status Marker] 🔘
* **Objective:** Catch and report every possible Web MIDI failure state.
* **Instructions:**
  1. Open `src/hooks/useWebMidi.ts`.
  2. Inside the `useEffect`, check support: If `!navigator.requestMIDIAccess`, call `setMidiAccessStatus('unsupported')` and `setMidiErrorText('Browser does not support Web MIDI')`.
  3. On `.then((access) => ...)`, call `setMidiAccessStatus('granted')`.
  4. On `.catch((err) => ...)`, call `setMidiAccessStatus('error')` and `setMidiErrorText(err instanceof Error ? err.message : String(err))`.
* **AGENT INSTRUCTION:** "Set Phase status to 🔵 Active. Instrument the hook promises. Once applied, set status to ✅ Completed."

### Phase 3: Surface Errors in UI (`Header.tsx`) — [Status Marker] 🔘
* **Objective:** Show the exact error or state in the dropdown area.
* **Instructions:**
  1. Open `src/components/Header.tsx`.
  2. Read `midiAccessStatus` and `midiErrorText` from the store.
  3. Replace the current `<select>` dropdown area with conditional rendering:
     * If `midiAccessStatus === 'unsupported'`, display a red text badge: "Browser Unsupported (Use Chrome/Edge)".
     * If `midiAccessStatus === 'error'`, display a red text badge: `Error: {midiErrorText}`.
     * If `midiAccessStatus === 'granted'` but `midiInputs.length === 0`, render the dropdown but change the empty option text to: "0 Devices (Check if DAW has exclusive lock)".
     * Otherwise, render the dropdown normally.
* **AGENT INSTRUCTION:** "Set Phase status to 🔵 Active. Edit the Header UI. Once applied, set status to ✅ Completed."
