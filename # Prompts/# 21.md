# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
**Feature:** "Harmonizer Monophony." When the user has Transpose Polyphony mode enabled, the physical Play Zone input must be restricted to strict monophony (Last-Note Priority).
**Objective:** Prevent muddy, overlapping chords and hung notes caused by legato playing. If the user holds Note A (triggering a transposed chord) and subsequently presses Note B, Note A's chord must be immediately silenced *before* Note B's chord is allowed to sound, even if the physical Note A key has not been released yet.

## 2. Technical Decisions
* **State Tracking:** Do not use Zustand for real-time key tracking. Introduce a `const activePlayNote = useRef<number | null>(null);` inside `useWebMidi.ts` to track the single active melodic note in the Play zone.
* **Interception Logic:** During a `Note On` event in the Play zone, if `polyphonyMode === 'poly'` and an `activePlayNote` already exists, the engine must manually trigger the `Note Off` cleanup for that previous note before processing the new one. 

## 3. Implementation Phases

### Phase 1: Play Zone Last-Note Priority — ✅ Completed
* **Objective:** Enforce strict monophony on the Play input when polyphonic mode is active, while leaving standard polyphony intact when in mono mode.
* **Instructions:**
    1. Open `src/hooks/useWebMidi.ts`.
    2. Near the top of the hook (with the other refs), declare: `const activePlayNote = useRef<number | null>(null);`
    3. Locate the Play Zone logic block (`else if (activeZone.type === 'play')`).
    4. **Inside the `isNoteOn` block:**
        * Check `if (state.polyphonyMode === 'poly')`.
        * If true, and `activePlayNote.current !== null` and `activePlayNote.current !== incomingNote`:
            * Fetch the previous note's data: `const prevNoteData = activeRoutedNotes.current.get(activePlayNote.current);`
            * If it exists, loop through its `outNotes`, trigger the visual feedback off, and send `Note Off` (0x80) messages to all `midiOutputs`.
            * Delete it from the map: `activeRoutedNotes.current.delete(activePlayNote.current);`
        * Update the tracker: `activePlayNote.current = incomingNote;`
        * *Then* proceed with the normal Polyphonic delta calculation and send the new `Note On` messages.
    5. **Inside the `!isNoteOn` (Note Off) block:**
        * Check `if (state.polyphonyMode === 'poly')`.
        * If true, check `if (activePlayNote.current !== incomingNote)`. If they do *not* match, **return early** and drop the Note Off message. (Crucial: if Note A was already silenced by Note B, physically releasing Note A later should not do anything).
        * If they *do* match, set `activePlayNote.current = null` and proceed with the normal Note Off cleanup.
* **TDD Checkpoint:**

    * **Test Case 2:** User physically releases C4 (which was already silenced). Assert no MIDI messages are sent and D4 remains playing.
    * **Test Case 3:** User releases D4. Assert D4 chord receives Note Offs.
