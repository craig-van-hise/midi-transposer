# Product Requirements Prompt (PRP) — VISUAL FEEDBACK & COLOR SYNC 🔘

## 1. Context & Objective
**STATUS: UX POLISH & HARDWARE FEEDBACK**
The MIDI pipeline is actively processing data, but the `KeySplitKeyboard` (Input) lacks visual hardware feedback, leaving the user blind to their physical inputs. Furthermore, the `TransposeKeyboard88` UI is currently colored blue, but it must be updated to **Red** to match the Input keyboard's Transpose zone, establishing a unified color-coded mental model.

## 2. Mandatory Execution Constraints
* **DO NOT** edit any `.md` files. 
* Target `.ts` and `.tsx` files ONLY.

## 3. Implementation Phases

### Phase 1: Transpose Keyboard Color Sync (Blue -> Red) — [Status Marker] 🔘
* **Objective:** Change all active UI elements in the Transpose card from Blue to Red/Rose.
* **Instructions:**
  1. Open `src/components/keyboards/TransposeKeyboard88.tsx`.
  2. Execute a search and replace for the following Tailwind classes and hex codes:
     * Replace `#3b82f6` (Blue hex) with `#f43f5e` (Rose/Red hex).
     * Replace `bg-blue-500` with `bg-rose-500`.
     * Replace `border-blue-500` with `border-rose-500`.
     * Replace `border-t-blue-500` with `border-t-rose-500`.
     * Replace `ring-blue-100` with `ring-rose-100`.
     * Replace the RGB shadow `rgba(59,130,246,0.6)` and `rgba(59,130,246,0.8)` with `rgba(244,63,94,0.6)` and `rgba(244,63,94,0.8)`.
* **AGENT INSTRUCTION:** "Set Phase status to 🔵 Active. Execute the color replacements in the Transpose component. Once applied, set status to ✅ Completed."

### Phase 2: Input Keyboard Zero-Latency Visual Feedback — [Status Marker] 🔘
* **Objective:** Light up the Input keyboard dynamically when physical MIDI notes arrive.
* **Instructions:**
  1. Open `src/hooks/useWebMidi.ts`.
  2. Locate `handleMidiMessage` where the incoming note variables are parsed:
     ```javascript
     const incomingNote = data[1];
     const velocity = data[2];
     const isNoteOn = statusType === 0x90 && velocity > 0;
     const state = useMidiStore.getState();
     ```
  3. Immediately below those variables (before checking the `bypass` state), insert the raw DOM manipulation logic for the Input keyboard:
     ```javascript
     // Zero-latency visual feedback for Input Keyboard
     const inputEl = document.getElementById(`pksplit-${incomingNote}`);
     if (inputEl) {
       const isBlack = [1, 3, 6, 8, 10].includes(incomingNote % 12);
       if (isNoteOn) {
         const zoneColor = incomingNote < state.splitPoint ? '#f43f5e' : '#3b82f6';
         inputEl.style.backgroundColor = zoneColor;
         inputEl.style.boxShadow = `0 0 12px ${zoneColor}, inset 0 0 6px rgba(255,255,255,0.4)`;
       } else {
         inputEl.style.backgroundColor = isBlack ? '#000000' : '#ffffff';
         inputEl.style.boxShadow = 'none';
       }
     }
     ```
* **AGENT INSTRUCTION:** "Set Phase status to 🔵 Active. Inject the DOM manipulation block into the event listener. Once applied, set status to ✅ Completed."
