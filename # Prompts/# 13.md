# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
**STATUS: SYSTEMS ENGINEERING & LOGIC PIVOT**
The layout is locked. We are now building the core functionality. The application acts as a real-time MIDI router and transposer. 
Space is split into exactly two zones:
1. **Transpose (Left):** Notes played here DO NOT go to the output. Instead, they dynamically update the global `transposeTarget` note.
2. **Play (Right):** Notes played here pass through the pipeline. They are transposed by the current delta (`transposeTarget - transposeOrigin`), filtered by the `NoteRangeFilterKeyboard` settings, and sent to the output.

## 2. Technical Decisions & Dependencies
* **State Management:** Use `zustand` to create a global store (`useMidiStore`). 
* **MIDI API:** Use the native browser `navigator.requestMIDIAccess()`.
* **Component Constraints:** The `KeySplitKeyboard` must lose its ability to add/delete zones or change channels. It is strictly a two-zone split (Transpose and Play), but the seam between them remains draggable, and the Octave knobs remain functional.

### Phase 5: The MIDI Routing Engine — [Status Marker] ✅ Completed
* **Objective:** Implement the real-time logic pipeline.
* **Instructions:**
  1. In `useWebMidi.ts`, implement the `onmidimessage` handler.
  2. Parse the MIDI message (Note On / Note Off).
  3. Get current state from `useMidiStore` (`splitPoint`, `transposeOctave`, `playOctave`, `transposeOrigin`, `transposeTarget`).
  4. **Logic Branch:**
     * **If incoming note < `splitPoint` (Transpose Zone):**
       * Apply octave shift: `effectiveNote = incomingNote + (transposeOctave * 12)`.
       * If Note On: Update `transposeTarget` in store to `effectiveNote`.
       * Do NOT send to MIDI output.
     * **If incoming note >= `splitPoint` (Play Zone):**
       * Apply octave shift: `effectiveNote = incomingNote + (playOctave * 12)`.
       * Calculate Delta: `delta = transposeTarget - transposeOrigin`.
       * Apply Delta: `finalNote = effectiveNote + delta`.
       * *(Note: Filter limits logic to be fully implemented in a later phase, for now just pass through if inside range)*.
       * Trigger visual UI on the Output Keyboard (simulate click/active state on the specific key).
