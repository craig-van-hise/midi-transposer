# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
**Bug Fix:** In Polyphonic mode, the default transpose value (`0` offset, usually note `60`) remains permanently stuck in the `transposeTargets` array because no physical `Note Off` is ever sent to clear it. Furthermore, polyphonic transpose input needs to properly "latch" chords.
**Objective:** Implement a physical key counter for the Transpose Zone. When a user starts playing a new chord (initial `Note On` when zero keys are currently held), it must overwrite the `transposeTargets` array. Subsequent notes held simultaneously should append to the array.

## 2. Technical Decisions
* **Tracking Physical Keys:** We cannot rely solely on the Zustand state for physical finger tracking. You must add a `const activeTransposeKeys = useRef<Set<number>>(new Set());` inside `useWebMidi.ts` to track exactly which keys in the Transpose zone are currently being held down by the user.

## 3. Implementation Phases

### Phase 1: Polyphonic Chord Latching — ✅ Completed
* **Objective:** Fix the "stuck zero" bug by overwriting the transpose array on new chord strokes.
* **Instructions:**
    1. Open `src/hooks/useWebMidi.ts`.
    2. At the top of the hook (near the other refs), add: `const activeTransposeKeys = useRef<Set<number>>(new Set());`
    3. Locate the Transpose Zone incoming note logic (`if (activeZone.type === 'transpose')`).
    4. Implement the following logic flow:
        * **If `isNoteOn`:**
            * Check `activeTransposeKeys.current.size`.
            * If `size === 0` (this is the first finger of a new chord hitting the keys): Call `setTransposeTargets([effectiveNote])`. (This implicitly erases the stuck `0` or previous chords).
            * If `size > 0` (they are rolling a chord, holding previous keys down): Grab the current array from Zustand, append `effectiveNote` (if not already present), and call `setTransposeTargets([...current, effectiveNote])`.
            * Finally, add the note to the physical tracker: `activeTransposeKeys.current.add(incomingNote);`
        * **If `!isNoteOn` (Note Off):**
            * Simply remove the finger from the tracker: `activeTransposeKeys.current.delete(incomingNote);`
            * *Crucial:* Do **not** remove the note from the Zustand `transposeTargets` array on Note Off. We want the chord to "latch" and stay active until the *next* time they press a key.
* **TDD Checkpoint:**
    * **Test Case 1:** Zustand starts at `[60]`. User plays Note On `48`. Assert `transposeTargets` becomes `[48]` (the `60` is gone).
    * **Test Case 2:** User continues holding `48` and plays Note On `52`. Assert `transposeTargets` becomes `[48, 52]`.
    * **Test Case 3:** User releases both keys. Assert `transposeTargets` remains `[48, 52]`.
